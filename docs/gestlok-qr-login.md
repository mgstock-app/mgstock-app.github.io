# Ingreso QR (piloto, no producción)
La PC genera dos secretos independientes de 256 bits. El QR contiene solo el secreto de escaneo; la PC guarda el secreto de canje en memoria. El servidor guarda hashes y un código de comparación. El teléfono requiere sesión Auth validada y mi_acceso activo, confirmación explícita del código y una sesión vigente. La PC consume el desafío bajo bloqueo antes de crear una sesión Supabase nueva; nunca copia el token de la sesión móvil. Caducidad 2 min, sin persistencia de pruebas en navegador. El login habitual y sus permisos no cambian.
Las cuentas con MFA deben usar ingreso habitual para no degradar seguridad. Si PWA y navegador tienen almacenamiento distinto, abrir Mi perfil → Vincular computadora y pegar el enlace o escanear en dispositivos compatibles. No requiere API paga.
Antes de producción: aplicar migración y función solo en entorno de pruebas, revisar RLS/privilegios, activar rate limit por IP confiable en infraestructura (el prototipo tiene límite global), probar concurrencia, rechazo de MFA, expiración, revocación, roles, phishing QR y origen; probar Android/iOS, PWA y navegador, Google/email y cierre local de PC. No publicar con solo tests estáticos.
